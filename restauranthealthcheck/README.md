# restauranthealthcheck.com

Restaurant Health Check — เครื่องมือตรวจเช็คสุขภาพธุรกิจร้านอาหาร 5 มิติ (PenguinX × CP)
พร้อมระบบบัญชีผู้ใช้ และการเก็บ lead

## โครงสร้าง

```
public/           ← เว็บที่คนเห็น (Cloudflare Pages เสิร์ฟโฟลเดอร์นี้)
  index.html        ตัวเครื่องมือ 8 หน้าจอ
  account.html      สมัคร / เข้าสู่ระบบ / ลืมรหัสผ่าน / ดูผลย้อนหลัง
  admin.html        หลังบ้าน — ดู lead ทั้งหมด กรอง และ export CSV
  privacy.html      นโยบายความเป็นส่วนตัว (PDPA)
  fonts/            ฟอนต์ Anuphan (แยกออกมาแล้ว ไม่ได้ฝัง base64)
  og.png robots.txt sitemap.xml
functions/        ← API (Cloudflare Pages Functions)
  _middleware.js    security headers + กันไม่ให้ error หลุดเป็น stack trace
  api/auth/*.js     signup · login · logout · verify · forgot · reset · me
  api/admin/*.js    login · logout · leads (รายการ+สถิติ) · lead (รายละเอียดรายคน) · export (CSV)
  api/assessments.js  บันทึกผลประเมิน + ดึงผลย้อนหลังของตัวเอง
lib/              ← โค้ดที่ใช้ร่วมกัน (อยู่นอก functions/ จึงไม่กลายเป็น URL)
  crypto.js         แฮชรหัสผ่าน (PBKDF2) + สร้าง/แฮช token
  admin.js          สิทธิ์ผู้ดูแล + ตัวกรองที่ใช้ร่วมกันระหว่างตารางกับ CSV
  session.js        session + token ใช้ครั้งเดียว
  ratelimit.js      จำกัดจำนวนครั้ง (ราย IP และรายอีเมล)
  email.js          ส่งอีเมลผ่าน Resend + เทมเพลตภาษาไทย 5 ฉบับ
  http.js           helper กลาง (JSON, cookie, ตรวจอีเมล/รหัสผ่าน)
migrations/       ← schema ของ D1
```

## ตั้งค่าครั้งแรก

```bash
npm install

# 1. สร้างฐานข้อมูล แล้วเอา database_id ที่ได้ไปใส่ใน wrangler.toml
npx wrangler d1 create restauranthealthcheck

# 2. สร้างตาราง
npm run db:remote        # บน Cloudflare (รันทั้ง 0001 และ 0002)
npm run db:local         # ในเครื่อง

# 3. ใส่ความลับ (ห้าม commit)
npx wrangler pages secret put RESEND_API_KEY
npx wrangler pages secret put MAIL_FROM
npx wrangler pages secret put SITE_URL
npx wrangler pages secret put ADMIN_PASSWORD    # รหัสเข้าหลังบ้าน
```

โดเมนผู้ส่งอีเมลต้องยืนยันที่ Resend ก่อน (ใส่ DNS: SPF + DKIM) ไม่งั้นเมลจะเข้าสแปม

## รันในเครื่อง

สร้างไฟล์ `.dev.vars` (gitignore ไว้แล้ว):

```

```

## ระบบบัญชีทำงานยังไง

- **รหัสผ่าน** แฮชด้วย PBKDF2-HMAC-SHA256 210,000 รอบ ผ่าน WebCrypto
  (Workers ใช้ bcrypt ไม่ได้) เก็บจำนวนรอบไว้ในตัวแฮช → เพิ่มรอบทีหลังได้
  โดยรหัสเดิมยังใช้ได้ และจะถูกอัปเกรดให้เองตอนล็อกอินครั้งถัดไป
- **token ทุกชนิดเก็บแบบแฮช** ทั้ง session, ลิงก์ยืนยันอีเมล และลิงก์รีเซ็ต
  → ต่อให้ฐานข้อมูลรั่ว ก็เอาไปสวมรอยล็อกอินหรือรีเซ็ตรหัสใครไม่ได้
- **ลิงก์ยืนยันอีเมล** อายุ 24 ชม. · **ลิงก์รีเซ็ตรหัสผ่าน** อายุ 30 นาที
  ทั้งคู่ใช้ได้ครั้งเดียว (ตัดจ่ายแบบ atomic กันกดพร้อมกันสองครั้ง)
- **ตั้งรหัสใหม่แล้วเตะทุกอุปกรณ์ออกจากระบบ** แล้วส่งเมลแจ้งเจ้าของบัญชี
- **ไม่บอกว่าอีเมลไหนมีบัญชี** — ทั้งหน้าสมัครและหน้าลืมรหัสผ่านตอบข้อความ
  เดียวกันเสมอ คนสมัครซ้ำด้วยอีเมลที่มีบัญชีแล้วจะได้เมลแจ้งแทน
- **เดารหัสผ่านผิดกับไม่มีบัญชี ตอบเหมือนกันและใช้เวลาเท่ากัน** (`fakeVerify`)
- **rate limit** ทุก endpoint ที่รับอีเมล นับทั้งราย IP และรายอีเมล
  สมัคร 10/ชม./IP · ลืมรหัส 3/ชม./อีเมล · ล็อกอิน 10/15นาที/อีเมล
- **cookie** `HttpOnly` + `Secure` + `SameSite=Lax` อายุ 30 วัน และ API ที่เขียน
  ข้อมูลจะปฏิเสธคำขอที่มาจากโดเมนอื่น

## การเก็บ lead

`submitLead()` ยิงไป `/api/assessments` **สองครั้งต่อหนึ่งคน**: ครั้งแรกทันทีที่
ลงทะเบียนเสร็จ อีกครั้งตอนได้ผลประเมิน ทั้งสองครั้งใช้ `sessionKey` เดียวกัน
จึงรวมเป็นแถวเดียว — **คนที่ทำไม่จบก็ยังถูกเก็บเป็น lead**

ถ้าเซิร์ฟเวอร์ล่มหรือเน็ตหลุด ข้อมูลจะถูกพักไว้ใน `localStorage` แล้วส่งใหม่
รอบหน้า (`flushLeads()` ทำงานตอนเปิดหน้าแรก) — ผู้ใช้ไม่มีทางติดค้าง

และถ้า **Resend ล่ม** การบันทึก lead ยังทำงานปกติ — `sendMail()` กลืน error
ทุกชนิด (ต่อไม่ติด, DNS, timeout, 4xx/5xx) แล้วคืน `ok:false` แทนที่จะโยนต่อ
พร้อม timeout 10 วิ กันคำขอค้าง **เมลเสียไม่ทำให้ lead หาย**

## ทดสอบ

```bash
npm run dev          # หน้าต่างที่ 1
npm run test:mail    # หน้าต่างที่ 2 — ดักอีเมลไว้ ไม่ให้ส่งจริง
npm test             # หน้าต่างที่ 3
```

**238 เคส ผ่านทั้งหมด** รันจริงบน wrangler + D1 ในเครื่อง:

| ชุด | เคส | ครอบคลุม |
|---|---|---|
| `crypto` | 18 | แฮชรหัสผ่าน, salt, ปฏิเสธรหัสผิด, timing, token |
| `auth` | 49 | สมัคร → ยืนยันเมล → ล็อกอิน → ลืมรหัส → ตั้งรหัสใหม่ → เตะ session เก่า → ใช้ token ซ้ำไม่ได้ → กัน cross-origin |
| `admin-email` | 45 | เมลสรุปผล (ไม่ส่งซ้ำ), สิทธิ์หลังบ้าน, ตัวกรอง, สถิติ, CSV ระดับ byte |
| `mail-outage` | 6 | ผู้ให้บริการอีเมลล่มแล้ว lead ยังไม่หาย |
| `ui-assessment` | 29 ×2 | **กดใช้งานจริงในเบราว์เซอร์** ทั้งเดสก์ท็อปและมือถือ ตั้งแต่หน้าแรกจนได้รายงาน |
| `ui-account-admin` | 30 | โหมดด่วน, หน้าบัญชี, หน้าหลังบ้าน — กดผ่าน UI จริง |
| `admin-detail` | 18 | รายละเอียดรายคน: สิทธิ์, id มั่ว, ตัวเลขการเงินแบบบาท |
| `ui-lead-detail` | 14 | กดแถว → เปิดแผง, ปุ่มโทร/เมล, ปิดด้วย Esc |

ชุด `ui-*` ใช้ Chromium จริงขับ ถ้ารันนอกเครื่องนี้ให้ตั้ง `CHROME_PATH`
ชี้ไปที่ Chrome ในเครื่องก่อน

> ตัวรันจะล้างตัวนับ rate limit ระหว่างชุด เพราะทุกชุดยิงจาก IP เดียวกัน
> ถ้าไม่ล้าง ชุดหลัง ๆ จะโดนลิมิตของชุดก่อนหน้า (ซึ่งเป็นพฤติกรรมที่ถูกต้องของระบบ)

## หลังบ้าน (`/admin`)

เข้าด้วยรหัสเดียวจาก secret `ADMIN_PASSWORD` — ผู้ดูแลไม่ใช่ user ไม่มีแถวใน `users`
ใช้คุกกี้คนละตัว (`rhc_admin`) และหมดอายุใน 12 ชม.

- ตัวเลขสรุป: คนทำทั้งหมด · ทำจบ (พร้อม %) · มีอีเมล · คะแนนเฉลี่ย · HOT/WARM/NURTURE
- กรองได้: คำค้น (ชื่อร้าน/ชื่อ/อีเมล/เบอร์) · tier · ประเภทร้าน · ทำจบ/ไม่จบ · ช่วงวันที่
- **export CSV** ใช้ตัวกรองชุดเดียวกับที่เห็นบนตาราง มี BOM และประกาศ `sep=,`
  → เปิดใน Excel ภาษาไทยแล้วไม่เป็นตัวยึกยือ และไม่ตกลงช่องเดียว
- **กดที่แถวเพื่อดูรายละเอียดรายคน** — เบอร์กดโทรออกได้ อีเมลกดส่งได้ทันที,
  คะแนนราย 5 มิติ, ตัวเลขการเงินเป็นบาทพร้อม %, สิ่งที่สนใจให้ช่วย,
  เวลายินยอม PDPA, ส่งเมลผลไปแล้วหรือยัง (กด Esc หรือคลิกนอกแผงเพื่อปิด)

> ถ้าผู้ใช้ไม่ได้แก้ตัวเลขต้นทุนเอง แผงจะขึ้นป้ายเตือนว่าเป็น**ค่าประมาณที่ระบบเดาให้**
> — อย่าเอาไปคุยกับเจ้าของร้านราวกับเป็นตัวเลขจริงของเขา

**ข้อจำกัดที่ต้องรู้:** SQLite ปฏิเสธ LIKE pattern ที่ยาวเกิน 50 **ไบต์**
ภาษาไทยตัวละ 3 ไบต์ → ชื่อร้านไทยเกิน ~16 ตัวอักษรจะเกินลิมิต
`buildFilter()` จึงตัดคำค้นตามจำนวนไบต์ (ไม่ใช่จำนวนตัวอักษร) ก่อนเสมอ

## เมลสรุปผล

ส่งอัตโนมัติเมื่อทำแบบประเมินจบ *และ* มีอีเมล — มีคะแนนรวม ประเภทร้าน และคะแนนราย
มิติทั้ง 5 พร้อมลิงก์กลับมาดูรายงานเต็ม เวลาส่งถูกบันทึกไว้ในคอลัมน์
`result_email_sent_at` (ตัดจ่ายแบบ atomic) จึงไม่มีทางส่งซ้ำ
ถ้าส่งไม่สำเร็จจะเคลียร์ค่ากลับ เพื่อให้ลองใหม่ได้

## ยังค้างอยู่

1. **ลิงก์ Google Form ของปุ่ม CTA** — `CONFIG.ctaUrl` ใน `public/index.html`
   ยังว่างอยู่ **ปุ่มจะถูกซ่อนไว้จนกว่าจะใส่ลิงก์** (ดีกว่าปล่อยให้กดแล้วไม่มีอะไรเกิด)
   ใส่แล้วปุ่มจะโผล่เอง และจะแนบ `rhc_sid` / `rhc_tier` / `rhc_type` ไปกับลิงก์ให้ด้วย
2. **`track()` ยังไม่ได้เก็บที่ไหน** — เขียนลง console อย่างเดียว
   ถ้าอยากได้ funnel ว่าคนหลุดตรงไหน ต้องทำ `/api/events` เพิ่ม
3. **ยังไม่มีปุ่มลบข้อมูลให้ผู้ใช้กดเอง** — PDPA บอกให้ขอลบได้ ตอนนี้ต้องเมลมาขอ
   แล้วทีมงานลบให้ด้วยมือ
